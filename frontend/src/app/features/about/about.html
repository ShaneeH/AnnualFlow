ReportHub

Fully Understand financial reports without reading a page.

ReportHub extracts key information from company financial reports, calculates performance metrics and presents everything through a clear, interactive dashboard.

Open dashboard How it works?

Why use ReportHub?

From lengthy PDF to useful financial insight

Company reports contain valuable information, but finding and comparing it can take time. Important figures are often buried across hundreds of pages and presented differently between companies.

ReportHub turns those documents into structured financial data, making it easier to understand performance, compare reporting periods and identify important changes.

Capabilities

Everything needed to analyse a report

1

Automatic extraction

AI assisted analysis identifies the company, reporting period and important financial values directly from the uploaded report.

2

Financial calculations

Revenue growth, margins, liquidity, leverage and other board level performance indicators are calculated automatically.

3

Period comparison

Compare financial periods side by side to quickly identify improvements, declines and wider performance trends.

4

Structured storage

Extracted information is validated, normalised and stored in PostgreSQL for consistent access across the platform.

5

Duplicate protection

SHA256 document fingerprinting prevents the same financial report from being processed more than once.

6

Interactive dashboard

Key values, comparisons and financial ratios are presented through a focused interface built for quick understanding.

How it works

Three steps from document to dashboard

1

Upload a report

Add a company financial report in PDF format. ReportHub validates the file and checks whether it has already been uploaded.

2

Process the information

The document is analysed and its financial information is converted into a consistent, validated structure.

3

Explore the results

View company performance, calculated KPIs and reporting period comparisons through the dashboard.

About Annualflow

An open source project by Shane Hahesy that turns financial report PDFs into structured data.

The home page gives an overview of what it does. This page covers how it is built, and the design decisions behind it. It also explains how to get involved.

Architecture

  1. Upload. The Express API checks the file's type, size and PDF signature. It then hashes the bytes with SHA-256 and refuses files it has already seen.
  2. Extraction. The PDF goes to the OpenAI Responses API with a strict JSON schema. The model also classifies the document, so a CV or invoice is identified as not being a report.
  3. Validation. The server re-checks everything the model returned: types, period codes, plausible values and at least one core metric. Anything that fails is rejected with a clear message, and nothing is written.
  4. Storage. The company, document, periods and links are written to PostgreSQL in a single transaction.
  5. Processing mode. Uploads run as background jobs on long-running hosts (JOB_MODE=async), or inside the request on serverless hosts (JOB_MODE=sync).

Data Enrichment: implementation notes

  • Companies are matched by name, ignoring case. Periods are matched by (company, period).
  • Each field is updated with COALESCE(new, existing). Incoming values replace stored ones, and a missing value never erases a stored one.
  • Before the update, fields where both values exist and differ are returned to the client as conflicts[], with the previous and new values.
  • The document_periods table links each period to every document that contributed to it. The dashboard shows this as the number of sources.
  • Margins and ratios are recalculated from the merged figures, and the period's cached Insights are cleared.

Design decisions

  • Calculations in code. The model only extracts reported figures. Margins, ratios and changes are calculated deterministically and covered by tests.
  • AI output is treated as untrusted input. It is validated twice: by the schema and again on the server.
  • Grounded summaries. Insights only receive the stored figures and is told not to invent numbers.
  • Idempotent migrations. Numbered SQL files run under an advisory lock, so re-running them is safe.
  • Rate limiting on uploads and AI requests, and typed errors with request IDs in the logs.
